## Context

当前仓库只有任务说明，没有既有代码、构建链或设计系统。目标是一个可直接在手机浏览器打开、可安装、可离线运行的静态游戏，因此不能依赖后端、框架运行时或外部 CDN。玩法与需求分别见 `proposal.md` 和 `specs/gold-miner/*/spec.md`，本文只记录实现层面的取舍。

## Goals / Non-Goals

**Goals:**

- 用零依赖的 HTML/CSS/JavaScript 实现完整单局循环与关卡成长，代码可在普通静态服务器和 `file://` 下运行。
- 在 390×844 级别的手机上保持 HUD 可读、触控区域充足、动画稳定在 60fps 目标附近。
- 把可测试的纯逻辑（目标曲线、回收速度、物品生成、存档清洗）抽离出来，使用 Node 内置测试运行。
- 生成可单文件传播的 `dist/gold-miner.html`，同时保留可维护的多文件源码结构。

**Non-Goals:**

- 不实现联网排行榜、账号、云存档、广告或内购。
- 不追求逐像素复刻某一款商业版本，也不使用其美术、音效或商标资源。
- 不支持 IE、旧版 Android WebView 等缺乏 Canvas 2D/Pointer Events 的环境。
- 不做多语言；界面文案固定为简体中文。

## Decisions

### 1. 原生 Canvas 2D + DOM 叠加层，而不是游戏引擎或框架

**选择**：游戏场景、角色、物品和粒子用 Canvas 2D 绘制；HUD、开始页、暂停页、结算页和商店用 DOM 覆盖层。

**理由**：没有构建依赖，首屏体积小，`file://` 可直接打开；DOM 按钮天然支持可访问性、44px 触控尺寸和文本排版，Canvas 负责高频动画。

**备选**：Phaser/PixiJS 功能更全，但会增加数百 KB 依赖、需要打包，并让单文件内联复杂化；纯 DOM/CSS 动画难以稳定处理绳索碰撞与粒子。

### 2. 固定逻辑宽度、自适应逻辑高度

**选择**：逻辑宽度固定为 540，逻辑高度按容器宽高比计算并限制在 780–1250 之间；渲染时按设备像素比（上限 2）缩放。

**理由**：手机上画布填满视口，不产生黑边；横向坐标和物品尺寸保持稳定，纵向多出的空间用于布置矿层。桌面端通过最大宽度约束保持竖屏街机比例。

**备选**：固定 540×900 并等比留黑边，实现简单但全面屏利用率低；直接拉伸画布会破坏圆形物品比例。

### 3. 单文件游戏循环 + UMD 纯逻辑模块

**选择**：`js/core.js` 暴露纯函数（目标、速度、生成计划、存档清洗），同时兼容浏览器全局与 CommonJS；`js/game.js` 负责状态机、渲染和输入。两者均为普通脚本，按顺序加载。

**理由**：普通脚本避免 `file://` 下 ES Module 的 CORS 限制，单文件构建只需按顺序内联；纯函数可在 Node 中直接测试，无需浏览器。

**备选**：ES Module 结构更现代，但单文件内联和本地文件打开都更麻烦；把所有逻辑塞进一个文件会降低可测性。

### 4. 显式状态机驱动流程

**选择**：使用 `menu / playing / paused / result / shop` 五个主状态；钩子另有 `swing / shoot / retract` 子状态。倒计时、道具计时和粒子只在 `playing` 更新。

**理由**：暂停、切后台、结算等待钩子返回等需求都依赖明确的状态边界；集中管理可避免计时器在弹窗后面继续跑。

**备选**：用布尔标志组合控制，状态一多容易互相矛盾。

### 5. 程序化美术与音效，不引入外部资源

**选择**：矿工、金块、石头、钻石、道具均用 Canvas 路径和渐变绘制；音效使用 Web Audio 振荡器与噪声合成；图标用 SVG 绘制。

**理由**：保持单文件体积小、无版权素材风险、离线可用；统一色板更容易形成完整视觉风格。

**备选**：位图精灵更易做出细节，但需要额外资源、打包和加载失败处理，且会显著增大单文件。

### 6. 先缓存背景，再逐帧绘制动态层

**选择**：在尺寸变化时把天空、岩层、木架、星点和纹理预渲染到离屏 Canvas；每帧只绘制角色、物品、绳索、粒子和 HUD 动效。

**理由**：静态纹理占画面大部分像素，预渲染能显著降低手机 GPU/CPU 压力；动态层对象数量少，维持 60fps 更稳。

**备选**：每帧重绘所有渐变和纹理，代码更直接但中低端手机容易掉帧。

### 7. 版本化 localStorage 与容错清洗

**选择**：存档键为 `goldMinerSave.v1`，读取时逐字段校验类型并限制范围；写入异常被捕获，游戏继续以内存状态运行。PWA 缓存同样使用版本化名称并在激活时删除旧缓存。

**理由**：移动浏览器可能禁用存储、隐私模式会抛异常、旧版本数据可能结构不同。容错清洗保证升级和异常环境不白屏。

### 8. 单文件构建与 PWA 并存

**选择**：保留 `index.html + css + js` 的源码形态用于部署与 PWA；`tools/build-single.mjs` 读取源码，内联 CSS/JS、把 SVG 图标转成 data URI，并移除 manifest 与 Service Worker 注册，输出 `dist/gold-miner.html`。

**理由**：同一套代码同时满足“部署到静态站点并安装”和“发一个文件到手机直接打开”。构建脚本无第三方依赖，便于重复执行。

**备选**：只维护单文件会牺牲可读性；只维护多文件则手机直接打开不方便。

## Risks / Trade-offs

- **移动端音频解锁失败** → 在首次 `pointerdown` 时创建并 `resume()` AudioContext；所有播放调用包裹 try/catch，失败时静默降级。
- **低端机 Canvas 掉帧** → 背景离屏缓存、设备像素比上限 2、粒子数量上限、`requestAnimationFrame` 默认节流、页面隐藏时停止循环。
- **横竖屏切换导致物品越界** → 重新计算逻辑高度后按比例缩放物品纵坐标并夹取到可抓取区域，不重置关卡状态。
- **难度失衡（目标过高或物品总价值不足）** → 生成后用总价值校验，必要时把石头升级为金块；目标曲线保持线性可预测。
- **单文件与 Service Worker 冲突** → 单文件在 `file://` 下跳过 SW 注册，构建时移除 manifest 链接；HTTP 部署时保留完整 PWA 能力。
- **搜索结果质量差/无法稳定联网调研** → 以经典系列公开且一致的玩法基线为准，不复制具体关卡数据或素材；规则在 proposal 中显式记录。
- **触摸误触与页面滚动** → 游戏容器 `touch-action: none`、禁止文本选择与回弹滚动；输入统一走 Pointer Events。

## Migration Plan

这是仓库内的全新项目，无既有数据或接口需要迁移。上线步骤：

1. 在仓库根目录用任意静态服务器托管（例如 `python -m http.server 8080`），验证桌面与手机浏览器。
2. 运行 `npm test` 校验纯逻辑，运行 `npm run build` 生成单文件。
3. 将源码目录部署到静态托管即可获得 PWA；将 `dist/gold-miner.html` 单独分发即可离线打开。
4. 如需回滚，删除新增的静态文件与 `dist/` 即可，不影响其他项目。
